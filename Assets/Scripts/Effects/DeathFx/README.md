# Death FX

Per-archetype enemy death effects: each enemy archetype dies with a visually distinct
burst — different colors, sizes, particle counts, sounds, gibs.

This system is **purely additive**. It does not modify `EnemyBase`, `EnemyHealth`,
`FxService`, `PoolService`, or any other existing file. It plugs in by:

1. Polling `EnemyRegistry.Enemies` to discover live enemies.
2. Attaching a small `DeathFxReporter` companion script to each one.
3. The reporter subscribes to `EnemyHealth.OnDied` and forwards the dying enemy
   back to the dispatcher.
4. The dispatcher resolves a `DeathFxProfile` from the `DeathFxRegistry` keyed by
   `EnemyData.displayName` and plays the burst.

Namespace: `LoneFighter.Effects.DeathFx`

## Files

| File                          | Role                                                       |
|-------------------------------|------------------------------------------------------------|
| `DeathFxProfile.cs`           | ScriptableObject — recipe (particle, sound, shake, gibs).  |
| `DeathFxRegistry.cs`          | ScriptableObject — `enemyName` → `DeathFxProfile` map.     |
| `DeathFxDispatcher.cs`        | MonoBehaviour singleton — poll + dispatch.                 |
| `DeathFxReporter.cs`          | MonoBehaviour — companion per enemy. Forwards `OnDied`.    |
| `GibSpawner.cs`               | MonoBehaviour singleton — sprays pooled gib chunks.        |
| `GibChunk.cs`                 | Pooled gib body + sprite, flies outward then fades.        |
| `Editor/DeathFxProfileGenerator.cs` | Editor menu that generates the 7 starter profiles.   |

## Quick start

1. **Generate profiles.** In Unity, open **LoneFighter → FX → Generate Death FX Profiles**.
   This creates:

   - `Assets/Data/DeathFx/DeathFxRegistry.asset`
   - `Assets/Data/DeathFx/Profiles/{Grunt|Runner|Tank|Spitter|Dasher|Bomber|Warden}.asset`
   - `Assets/Data/DeathFx/Gibs/GibChunkSprite.png`
   - `Assets/Data/DeathFx/Gibs/GibChunk.prefab`

   Re-running the menu is safe — fields update in place, the registry mapping is
   re-wired, and the gib sprite/prefab are left alone if they already exist.

2. **Add to scene.** On the `Systems` parent GameObject (the same one that hosts
   `FxService`, `PoolService`, `AudioManager`, etc.):

   - Add a `DeathFxDispatcher` component. Drop the generated `DeathFxRegistry.asset`
     onto its `registry` field.
   - Add a `GibSpawner` component. Drop the generated `GibChunk.prefab` onto its
     `gibChunkPrefab` field.

3. **(Optional) Wire particle prefabs per profile.** Each profile has an optional
   `particlePrefab` field. If left null, the dispatcher falls back to
   `FxService.EnemyExplosion` (the default explosion). If set, the dispatcher
   pools the prefab, applies the profile's `particleTint` / `particleSizeMultiplier`
   / `particleBurstCount`, and plays it. The HDR colors generated by the menu
   are sized for the additive bloom material in `Assets/Settings/Fx_Additive.mat`,
   so reusing `Assets/Prefabs/Fx/Fx_EnemyExplosion.prefab` as the base prefab is
   the path of least resistance.

4. **Play.** Kill an enemy → its archetype's profile fires (particle burst, gib
   spray, screen shake, hit-stop, sound cue).

## Profile fields (`DeathFxProfile`)

| Field                     | Purpose                                                                 |
|---------------------------|-------------------------------------------------------------------------|
| `particlePrefab`          | Optional ParticleSystem prefab pooled & played. Null → FxService default. |
| `particleTint`            | HDR tint applied to `main.startColor`. Alpha 0 = keep prefab color.     |
| `particleSizeMultiplier`  | Multiplies `main.startSizeMultiplier`.                                  |
| `particleBurstCount`      | Overrides the prefab's first emission burst count. 0 = keep prefab's.   |
| `soundCueName`            | String name of an `AudioCue` enum value. Falls back to `EnemyDeath`.    |
| `soundVolumeScale`        | 0..1 multiplier passed to `AudioManager.Play`.                          |
| `shake`                   | `None` / `Light` / `Heavy` — maps to `FxService.LightShake/HeavyShake`. |
| `hitStopSeconds`          | 0..0.25s. 0 disables.                                                   |
| `gibCount`                | 0..32 chunks. 0 disables gibs.                                          |
| `gibColor`                | Tint on the chunks' SpriteRenderer.                                     |
| `gibSizeRange`            | `(min, max)` uniform scale on each chunk.                               |
| `gibSpeedRange`           | `(min, max)` launch speed on each chunk.                                |
| `gibLifetime`             | Seconds before each chunk fades out and returns to pool.                |
| `splatDecalColor`         | Color of the ground splat decal. Alpha 0 = no decal. (Splat decal       |
|                           | renderer is owned by a separate system — this profile only ships color.)|

## How it hooks into existing systems

- **No edits to `EnemyBase` or `EnemyHealth`.** Subscription happens through
  `DeathFxReporter`, a companion `MonoBehaviour` the dispatcher adds at runtime
  to each enemy it observes via `EnemyRegistry.Enemies`. The reporter listens to
  `EnemyHealth.OnDied`.
- **Reuses `FxService`** for camera shake (`LightShake` / `HeavyShake`) and
  hit-stop (`HitStop`).
- **Reuses `AudioManager`** for sound cues — the profile carries a string name
  parsed against `AudioCue` at runtime, so adding new cues to the enum doesn't
  require recompiling this folder.
- **Reuses `PoolService`** for both the particle prefab and the gib chunk prefab,
  so death effects don't trigger GC spikes during peak combat.
- **`DeathFxReporter` survives pool reuse** — `DisallowMultipleComponent` plus a
  GetComponent guard in `AttachReporter` make the dispatcher's poll idempotent.

## Notes & gotchas

- The registry's lookup is **case-insensitive** and trims whitespace. `"Grunt"`,
  `"grunt"`, and `" Grunt "` all hit the same entry.
- The lookup key is `EnemyData.displayName` — **not** the SO file name. The
  canonical names live in `LoneFighter.Data.ContentSeed.Enemies[]` (`Grunt`,
  `Runner`, `Tank`, `Spitter`, `Dasher`, `Bomber`, `Warden`).
- The dispatcher polls every `pollInterval` seconds (0.1s by default). At the
  game's peak ~6 spawns/sec and ~120 concurrent enemies, that's ~12 GetComponent
  calls/sec on first-discovery — negligible. The dispatcher does not allocate
  on the hot path (death event).
- `splatDecalColor` is ship-ready data but rendering the decal is **out of scope**
  for this folder. A future splat-decal renderer can read it via
  `DeathFxRegistry.Resolve(displayName).splatDecalColor`.
- `GibSpawner.maxBurstCount` caps a single Spawn call at 24 by default — guards
  against a misconfigured profile flooding the pool.
- If the registry is missing or a profile has no `particlePrefab`, the dispatcher
  falls back to `FxService.EnemyExplosion` + `LightShake` so death always has
  some feedback. Toggle `fallbackToFxServiceDefaults` on the dispatcher to
  disable that behavior.
